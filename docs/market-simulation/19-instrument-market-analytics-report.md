# 종목 시장 분석 보고서

## 목적과 경계

`GET /api/stock/v1/markets/order-book-instruments/{symbol}/market-report`는 가장 최근에 완료된 전체 장마감 시점의 종목 보고서를 반환한다. `/reports`는 종가와 거래실적, 기간 성과, 거래활동, 참가자 수급, 마감 보유 구조, 기업 이벤트, 동일 기준일 시장 비교, 데이터 품질을 표시한다.

이 API는 실시간 주문장 화면이 아니다. 현재가, 현재 최우선 호가, 현재 호가 깊이, 예상 슬리피지, 현재 미체결 주문, 현재 발행 인수기관 계좌·현금·자동 주문 설정을 포함하지 않는다. 조회 시점의 운영 상태를 마감 통계와 섞지 않는다.

## 설계 근거

- KRX 정보데이터시스템은 개별종목 시세·시가평가 추이와 투자자별 거래실적을 거래일 통계로 제공한다.
- SEC Market Structure Data는 스프레드와 호가 깊이를 개별 종목·날짜의 주문·호가 데이터로 산출한다.
- SEC Rule 605 체결 품질 통계는 주문 접수 당시 호가와 체결 결과를 결합하며, 단일 현재 호가를 과거 기간의 유동성으로 사용하지 않는다.

따라서 이 시스템도 마감 스냅샷과 기간 체결 원장은 종목 보고서에 사용하지만, 과거 호가 원장이 없는 스프레드·깊이·가격 충격은 산출하지 않는다. 주문 접수·취소·완전체결 시간은 종목 성과가 아니라 주문 경로와 체결 엔진의 집행 품질에 좌우되므로 별도 시장운영 보고서의 책임으로 둔다.

참고:

- https://data.krx.co.kr/contents/MDC/MAIN/main.jspx
- https://www.sec.gov/data-research/market-structure-data
- https://www.sec.gov/rules-regulations/staff-guidance/trading-markets-frequently-asked-questions/frequently-asked-questions-rule-605-regulation-nms

## 기준 시점

`reportDate`는 다음 조건을 모두 만족하는 가장 최근 스냅샷 날짜다.

1. `stock_market_close_run.symbol is null`
2. `stock_market_close_run.status = 'COMPLETED'`
3. 해당 실행의 `stock_order_book_daily_snapshot.symbol`이 조회 종목과 일치
4. 스냅샷 날짜가 현재 시뮬레이션 날짜보다 늦지 않음

동일 날짜에 전체 마감이 반복되면 `close_run_id`, `snapshot.id`가 가장 큰 행을 사용한다. 종목 단독 수동 마감은 기준일이 될 수 없다. 장 시작 전이나 장중의 현재 거래일도 전체 마감 전에는 보고서에 들어가지 않는다.

## 데이터 원장

| 영역 | 원장 | 시점 규칙 |
| --- | --- | --- |
| 종가·전일 종가·발행/유통주식 | `stock_order_book_daily_snapshot` | 선택된 전체 마감 스냅샷의 값을 그대로 사용한다. `stock_price` 현재값으로 보충하지 않는다. |
| 기준일 OHLC·VWAP·거래량·거래대금 | `stock_execution` | `[reportDate 00:00, reportDate+1 00:00)`의 `INTERNAL_ORDER_BOOK`, `BUY` 원장만 집계해 매수·매도 이중 기록을 제거한다. |
| 일별 이력 | `stock_order_book_daily_snapshot`, `stock_market_close_run` | `reportDate` 이하의 전체 마감 최신 스냅샷만 사용한다. |
| 거래활동·체결 빈도 | `stock_execution` | `reportDate`까지 최근 최대 20거래일 체결 건수·수량·간격만 사용한다. `BUY` 원장만 집계해 양방향 기록을 중복 계산하지 않는다. |
| 참가자 수급 | `stock_execution`, `stock_account`, 참가자 설정 | 기준일·5거래일·20거래일 체결만 일반/자동/주관사 유형으로 집계한다. |
| 보유 구조 | `stock_holding_snapshot` | 선택된 `close_run_id`의 계좌별 보유 스냅샷만 사용한다. 현재 `stock_holding`은 사용하지 않는다. |
| 기업 이벤트 | `stock_corporate_action`, 권리 원장 | `created_at < reportDate+1`인 이벤트만 포함한다. 상태는 기준일까지의 `applied_at`, `paid_at`, `listed_at`으로 복원한다. 현재 권리 진행률은 표시하지 않는다. |
| 시장 비교 | 동일 날짜의 일별 스냅샷 | 같은 `reportDate` 전체 마감 스냅샷이 있는 활성 종목만 비교한다. 현재가 fallback은 없다. |
| 관리자 평가 | `stock_instrument_report_event` | 사실 통계와 분리된 작성자 의견으로 표시하고 작성 시각을 노출한다. |

## 응답 영역

- 최상위: 기준일 종가, 전일 종가, 등락, 기준일 발행·유통주식, 시가총액, 가격제한 범위
- `performance`: 5/20/60거래일 수익률, 20개 일간 수익률 변동성, 고저가·낙폭, 직전 20거래일 평균 거래량·거래대금·회전율 비교, 가격·거래량 이력
- `tradingActivity`: 최근 20거래일 체결 건수·체결 수량·평균 체결 크기·평균 체결 간격
- `investorFlow`: 기준일/5일/20일 계정 유형별 매수·매도·순매수·순현금흐름, 계정 유형 거래 비중, 최대 계좌 거래 집중도
- `ownership`: 기준 마감의 보유 계좌 수, 보유 원장 커버리지, 상위 1/5계좌 보유 집중도, 발행·유통주식 변화
- `corporateActions`: 기준일까지 공시된 이벤트의 기준일 당시 상태·일정·가격·희석·배당·분할과 전후 마감 비교
- `rankings`: 동일 기준일 종목의 시가총액·거래대금·거래량·등락률·회전율·20일 변동성 순위와 유사 시가총액 종목
- `dataQuality`: 기준일, 마감 완료 여부, 가격·체결 시각, 보유 이력 범위, 포함하지 못하는 데이터

## 계산식

- 기간 수익률: `(기준일 종가 - N거래일 전 종가) / N거래일 전 종가 × 100`
- 20일 변동성: 최근 21개 종가로 만든 20개 일간 수익률의 표본 표준편차
- 고점 대비 하락률: `(기준일 종가 - 최근 20거래일 체결 최고가) / 최고가 × 100`
- 기준일 상대 거래량: `기준일 거래량 / 기준일 제외 직전 최대 20거래일 평균 거래량 × 100`
- 기준일 상대 거래대금: `기준일 거래대금 / 기준일 제외 직전 최대 20거래일 평균 거래대금 × 100`
- 유통주식 회전율: `거래량 / 기준일 유통주식수 × 100`
- 평균 체결 크기: `기간 체결 수량 / 기간 체결 건수`
- 평균 체결 간격: `(마지막 체결 시각 - 첫 체결 시각) / (체결 건수 - 1)`
- 수급 순매수: `매수 수량 - 매도 수량`
- 수급 순현금흐름: `매도 순유입 - 매수 순유출`
- 보유 집중도: `상위 계좌 보유수량 / 기준일 발행주식수 × 100`
- 예상 희석률: `신규 주식 / 이벤트 후 예상 발행주식 × 100`

이벤트 전후 가격은 이벤트 기준일과 7일 이내의 가장 가까운 전체 마감만 인정한다.

## 의도적으로 산출하지 않는 항목

- 현재 또는 과거 최우선 호가, 호가 깊이, 스프레드, 잔량 불균형, 예상 슬리피지
- 체결 당시 호가가 필요한 유효 스프레드·실현 스프레드·가격 개선·가격 충격
- 주문 취소율·거절률·완전체결률·최초/완전체결 시간 같은 주문 집행 품질
- 현재 미체결 주문, 자기교차 가능 주문, 주관사 운영 설정과 계좌 현금
- 재무제표 기반 EPS/BPS/PER/PBR/ROE, 실적 전망, 목표주가
- 실제 개인·기관·외국인 수급, 보호예수 비율
- 기준일 당시 개별 권리 청약·납입 진행률

이 값은 현재값이나 다른 지표에서 추정하지 않는다. 필요하면 먼저 일중 호가 스냅샷, 참가자 법적 분류, 재무·공시, 기업 이벤트 상태 이력 원장을 설계한다.

## 성능과 갱신

- 마감 보고서는 5분 주기로 갱신한다. 실시간 시세 폴링 주기를 사용하지 않는다.
- 기간 체결은 최근 최대 20거래일로 제한하고 `source, symbol, side, executed_at` 커버링 인덱스를 사용한다. 보고서 본문은 고비용 원시 주문 상태 집계를 수행하지 않는다.
- 일별 이력은 날짜별 최신 전체 마감을 고른 뒤 최근 61개만 반환한다.
- 시장 순위는 동일 기준일 스냅샷끼리만 비교하므로 현재 주문장 조회가 발생하지 않는다.

## 검증

1. `./gradlew :stock-back-service:test`
2. `npm run lint && npm run build && npm run verify:contract`
3. 실제 MySQL의 모든 보고서 종목이 HTTP 200인지 확인한다.
4. 응답 `reportDate`, 종가, 발행·유통주식이 선택된 전체 마감 스냅샷과 같은지 대조한다.
5. 기준일 거래량·거래대금이 `BUY` 체결 원장 합계와 같은지 대조한다.
6. 보유 집중도가 같은 `close_run_id`의 `stock_holding_snapshot` 합계와 같은지 대조한다.
7. 다음 거래일 장중에도 보고서 핵심 값과 시장 순위가 이전 전체 마감일을 유지하는지 확인한다.
8. 응답과 화면에 현재 호가·현재 주문·현재 보유·현재 주관사 설정 필드가 없는지 계약 테스트로 확인한다.
